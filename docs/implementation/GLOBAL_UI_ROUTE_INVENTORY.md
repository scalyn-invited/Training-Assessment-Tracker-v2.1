This is the migration checklist, not a completion claim. Source: the local integration of `ui/settings-figma` at `440fcc8` and fetched `origin/main` at `7bcef2c`, merge `a5a9334`. Paths below are relative to `apps/web/app`. `page.tsx` is the entry component unless another component is named. A Global Admin does not automatically receive client training, sensitive assessment or reviewer access.

## Existing shells and common states

- **F**: All authenticated pages use `ApplicationShell` through `AppShell`; there is no pathname allowlist or old-shell fallback. Platform users retain the reference sidebar/mobile bar. Learning navigation retains role predicates, client selection, unsaved-work guards and a native mobile menu. Client-required routes keep the loading/selection boundary. Denied platform visitors see authorized learning navigation plus the existing page denial.
- **L**: Historical legacy authenticated shell, removed in the shell-retirement checkpoint below. Earlier evidence describing L is preserved as history.
- **G**: `Guest` wraps `AppShell`; unresolved sessions now use shared `GuestShell` without authenticated navigation. Login, setup and account-link pages continue to force guest layout even for a signed-in visitor.
- **R**: Redirect only. **S**: Standalone shared RecoveryFrame without AppShell/session/branding requests.
- Authenticated routes require session-pending/error/retry, revoked access, brand loading/error/retry, theme precedence and shell navigation checks. Shared dialogs include Personal settings and the learning mobile menu, in addition to page dialogs below.
- Each bounded migration must keep information order and existing action grouping. Applying existing components/tokens is authorized; changing workflows or inventing a different page layout requires confirmation first.
